# EGX Analyzer

منصة تحليل فني ومالي لأسهم البورصة المصرية (EGX): أسعار لحظية، أخبار، تحليل
فني متعدد المؤشرات (Confluence System)، وباك-تيستنج لقياس الأداء الفعلي
تاريخيًا.

## المصادر
- **الأسعار اللحظية والبيانات الأساسية:** صفحة كل سهم على [مباشر](https://www.mubasher.info) (`/markets/EGX/stocks/{symbol}`)
- **الأخبار:** صفحة "آخر الأخبار" الحية على مباشر (`/news/eg/now/latest`) - **ملحوظة:** الـ RSS الرسمي لمباشر (`feeds.mubasher.info`) توقف عن التحديث فعليًا منذ يناير 2021 (تم التأكد بالفحص المباشر)، لذلك تم استبداله بصفحة الأخبار الحية كمصدر أساسي، مع إبقاء الـ RSS كخطة احتياطية فقط في `get_news_rss_fallback()`
- **البيانات التاريخية (OHLCV):** [Yahoo Finance](https://finance.yahoo.com) عبر مكتبة `yfinance`، برمز السهم + لاحقة `.CA` (مثال: `COMI.CA`)

## التركيب

```bash
python -m venv venv

pip install -r requirements.txt
cp .env.example .env            # اختياري - القيم الافتراضية تكفي للتشغيل المحلي
```

## التشغيل

**التيرمنال الأول - الـ API (والجدولة التلقائية للتنبيهات تبدأ معاه تلقائيًا):**
```bash
uvicorn app.api.main:app --reload --port 8000
```

**التيرمنال الثاني - التطبيق الشخصي (Streamlit، متعدد الصفحات):**
```bash
streamlit run frontend/app.py
```
هتفتح تلقائيًا في المتصفح على `http://localhost:8501` بتطبيق من 7 صفحات
(تظهر في القائمة الجانبية بأسماء عربية صريحة):
- **🏠 الرئيسية**
- **📊 الأسهم** — الأسعار اللحظية لأي مجموعة أسهم
- **🚀 فرص صاعدة** — فحص تلقائي لكل الأسهم وعرض اللي استوفت شروط الصعود فقط
- **📰 الأخبار** — آخر أخبار البورصة المصرية (من صفحة حية، وليس RSS متجمد - راجع قسم "مصادر البيانات" تحت)
- **🎯 التوصيات** — تقرير تحليل شامل لسهم واحد (فني + خطة تداول + باك-تيستنج + بيانات أساسية) مع زرار حفظ للمتابعة
- **📜 سجل التوصيات** — التوصيات المحفوظة، حالتها الحالية، وأداء النظام الفعلي من نتائج حقيقية مسجّلة
- **⚙️ الإعدادات** — تفعيل تنبيهات تليجرام (اختياري، معطّل افتراضيًا)، قايمة المتابعة الشخصية، وفحص يدوي

> هذه الواجهة مخصصة للاستخدام الشخصي المحلي فقط (تشتغل على جهازك، مش على
> الإنترنت). لو عايز تستخدمها من موبايلك وأنت في نفس شبكة الواي فاي، شغّل
> Streamlit بـ `--server.address 0.0.0.0` وافتح `http://<IP جهازك>:8501` من الموبايل.

بعد تشغيل الـ API فقط (بدون الواجهة):
- التوثيق التفاعلي (Swagger): http://127.0.0.1:8000/docs
- الصفحة الرئيسية: http://127.0.0.1:8000/

## نظام التوصيات (Confluence System)

كل مؤشر يصوّت: `+1` (صاعد) / `-1` (هابط) / `0` (محايد). الأصوات تتجمع داخل
4 فئات (اتجاه، زخم، تذبذب، حجم) بأوزان قابلة للتعديل في `app/config.py`
(`CATEGORY_WEIGHTS`)، ثم تتحول لدرجة نهائية (`score`) من -100 إلى +100:

| الدرجة | التوصية |
|---|---|
| ≥ 50 | شراء قوي |
| ≥ 20 | شراء |
| -20 إلى 20 | محايد / انتظار |
| ≤ -20 | بيع |
| ≤ -50 | بيع قوي |

## ⚠️ تنبيهات مهمة قبل الاستخدام الفعلي

1. **لا ضمانات.** لا يوجد نظام تحليل فني يضمن نسبة نجاح مرتفعة. `agreement_percent`
   في `/analysis` يقيس توافق المؤشرات **الآن فقط**، وهو **ليس** نسبة نجاح متوقعة.
2. **نسبة النجاح الحقيقية** الوحيدة المعتمدة في هذا المشروع هي تلك المحسوبة
   فعليًا من `/backtest` على بيانات تاريخية حقيقية - راجعها دائمًا قبل الثقة
   في أي توصية.
3. **اختبر الاستقرار.** جرّب `/backtest` بفترات (`1y`, `2y`, `5y`) وإعدادات
   `holding_days` مختلفة على نفس السهم. تذبذب كبير في النتائج = النظام غير
   مستقر (overfitted) على ظرف سوقي معين. استخدم `/backtest/{symbol}/walk-forward`
   و`/backtest/{symbol}/train-test-split` للتحقق من الاستقرار برقم صريح
   بدل التخمين، و`/backtest/{symbol}/by-market-regime` للتأكد إن الأداء
   مش مدفوع بس بموجة صعود عامة في السوق.
   ملحوظة منهجية: نظام التصويت قواعد ثابتة (مش بيتعلم من البيانات)، فـ
   "Walk-Forward" هنا يعني اختبار استقرار نفس القواعد الثابتة عبر الزمن،
   وليس إعادة ضبط معاملات - التفاصيل في تعليقات `app/backtesting/robustness.py`.
4. هذا المشروع أداة مساعدة للتحليل، **وليس نصيحة استثمارية**. راجع مستشارًا
   ماليًا مرخّصًا واستخدم إدارة مخاطر حقيقية (وقف خسارة، تنويع) قبل أي قرار
   تداول فعلي.

## قائمة الأسهم الموسّعة

`app/data/egx_symbols.json` فيه 39 سهم منسّق يدويًا (رمز + اسم عربي + قطاع)، متاحة عبر
`/symbols`. **مهم:** دي قائمة منسّقة يدويًا مش مستخرجة آليًا لحظيًا - صفحة الشركات
المدرجة على مباشر معتمدة على جافاسكريبت، وموقع البورصة المصرية الرسمي (egx.com.eg)
رافض الوصول الآلي وقت إعداد المشروع. تحقق من أي رمز مهم ليك عبر
`mubasher.info/markets/EGX/stocks/{symbol}` قبل الاعتماد الكامل عليه، وزوّد الملف
براحتك - هو مجرد JSON بسيط.

في صفحة 🚀 فرص صاعدة، تقدر تحمّل القائمة كاملة أو تفلترها بقطاع معين بضغطة زرار
بدل كتابة الرموز يدويًا.

## نظام التنبيهات (اختياري - معطّل افتراضيًا)

المنصة تقدر تبعتلك تنبيهات عبر تليجرام لما:
- سهم في قايمة متابعتك يستوفي شروط شراء صالحة (Score + توافق مؤشرات + R:R مقبول)
- توصية محفوظة تحقق هدف، أو ينكسر وقف الخسارة بتاعها

**التنبيهات معطّلة تمامًا لحد ما تفعّلها بنفسك** من صفحة ⚙️ الإعدادات:
1. اعمل بوت تليجرام مجاني عبر [@BotFather](https://t.me/BotFather) واحصل على الـ Bot Token
2. ابعت أي رسالة للبوت واحصل على الـ Chat ID بتاعك عبر [@userinfobot](https://t.me/userinfobot)
3. حط البيانات دي في صفحة الإعدادات، فعّل التنبيهات، واضغط "ابعت رسالة تجربة" للتأكد

الفحص **تلقائي بالكامل** طول ما الـ API شغال - `app/scheduler.py` بيبدأ
مع تشغيل `uvicorn` مباشرة (APScheduler، فحص كل 15 دقيقة) بدون أي جدولة
خارجية أو زرار يدوي. الأزرار في صفحة الإعدادات لسه موجودة لو عايز تتأكد
فورًا بدل ما تستنى الدورة الجاية. `GET /scheduler/status` يوضح هل الجدولة
شغالة حاليًا.

⚠️ الفحص التلقائي بيشتغل طول ما السيرفر (uvicorn) شغال على جهازك - لو
قفلت السيرفر، الفحص بيقف معاه (مش خدمة سحابية دائمة).

## الشكل الاحترافي والتنسيق

الواجهة كلها بتستخدم:
- **بادجات ملوّنة للتوصيات** (أخضر للشراء، أحمر للبيع، أصفر للمحايد) بدرجتين لكل لون (عادي/قوي) - `render_recommendation_badge()` في `api_client.py`
- **تنسيق أرقام موحّد** في كل مكان عبر `formatters.py`: أسعار بخانتين عشريتين وفواصل آلاف، نسب مئوية بإشارة واضحة (+/-)، أرقام كبيرة مختصرة (مليون/مليار)، ونسب R:R بصيغة `1:X.XX` جاهزة
- **جداول بيانات باستخدام `pandas.Styler`** بدل النصوص الخام - الأرقام بتفضل رقمية (تفرز صح) لكن بتتعرض منسّقة وملوّنة (أخضر للتغيير الموجب، أحمر للسالب)

كل دوال التنسيق بترجع "—" بدل ما ترمي استثناء لو استقبلت `None` أو قيمة غير رقمية - مفيش شاشة هتتعطل بسبب قيمة ناقصة.

## رادار السوق الكامل (~229 سهم بدل 39)

القائمة المنسّقة يدويًا (`egx_symbols.json`) فيها 39 سهم بس. لتغطية أوسع،
`app/data/stockanalysis_client.py` بيجيب **القائمة الكاملة لكل الأسهم
المُدرجة في EGX (~229 سهم)** من stockanalysis.com، ويخزّنها محليًا في كاش
(`egx_symbols_full_cache.json`) بعد أول جلب ناجح. لو المصدر الحي فشل لأي
سبب، النظام بيرجع تلقائيًا للقائمة المنسّقة (39 سهم) بدل ما ينهار.

- `GET /symbols/full-market` — القائمة الكاملة (من الكاش أو المصدر الحي)
- `GET /opportunities/top?use_full_market=true` (الافتراضي) — الرادار
  بيفحص كل الـ229 سهم **بالتوازي** (حتى 8 فحوصات في نفس الوقت) بدل الفحص
  التتابعي البطيء، عشان الوقت يفضل معقول رغم العدد الكبير
- زرار "🛰️ رادار السوق كامل" في صفحة 🚀 فرص صاعدة يحمّل نفس القائمة

## Data Quality Validation

قبل أي تحليل، `app/data/quality.py` بيفحص بيانات OHLCV الخام: بيانات
ناقصة، شمعات مكررة، ترتيب زمني غلط، OHLC غير منطقي (أعلى<أدنى)، حجم
تداول سالب، وتحرك سعري مفاجئ (احتمال انقسام سهم غير معدّل). لو فيه مشكلة
جوهرية، **الـ Score بيتقيّد تلقائيًا (بين -49 و+49)** عشان تمنع أي "إشارة
قوية" مبنية على بيانات مش موثوقة - النتيجة بتظهر في حقل `data_quality`
بكل استجابة `/analysis`، مع تحذير "DATA QUALITY WARNING" صريح في الواجهة.

## خطة مضاربة قصيرة بنسب ثابتة (5% هدف / 1.5% وقف)

جنب الخطة القياسية (المبنية على ATR/دعم/فيبوناتشي وبتدي نسب متغيّرة حسب
تذبذب كل سهم)، فيه خطة تانية مستقلة تمامًا في `speculative_trade_plan`
لكل استجابة `/analysis`: **نسب مئوية ثابتة بغض النظر عن تقلب السهم** -
افتراضيًا وقف خسارة 1.5% مقابل هدف 5% (R:R ≈ 1:3.3)، وده أسلوب شائع في
المضاربة القصيرة/اليومية حيث المتداول بيفكر بالنسبة المئوية مباشرة.

- `GET /analysis/{symbol}?speculation_stop_loss_pct=1.5&speculation_target_pct=5.0`
  — النسب قابلة للتخصيص بالكامل
- صفحة 🎯 التوصيات بتعرض الخطتين **جنب بعض** للمقارنة المباشرة، مع إمكانية
  تعديل نسب المضاربة لحظيًا من الواجهة
- لو R:R الناتج من النسب المحددة أقل من 1:1.5، الفرصة بترفض بنفس منطق
  الخطة القياسية - مفيش استثناء لخطة المضاربة من قاعدة الحد الأدنى

## الدعم والمقاومة بفيبوناتشي في خطة التداول

`app/risk/position.py` بقى بياخد مستويات فيبوناتشي (من `patterns.fibonacci_levels`)
كمصدر أساسي - مش بس أعلى/أدنى سعر بسيط - لحساب:
- **الدعم/وقف الخسارة**: أقرب مستوى فيبوناتشي تحت سعر الدخول (لو متاح ومنطقي)
- **الأهداف**: مستويات فيبوناتشي المتتالية فوق سعر الدخول (لو كل واحد بيحقق حد أدنى معقول من R:R)

لو مفيش مستويات فيبوناتشي مناسبة (مثلًا السهم عند قمة تاريخية جديدة)، النظام
بيرجع تلقائيًا لمضاعفات المخاطرة (ATR-based) - فيبوناتشي مصدر أساسي مش
الوحيد. حقل `trade_plan.based_on_fibonacci` يوضح هل الخطة اعتمدت على
فيبوناتشي فعلًا ولا لأ.

## رسم بياني احترافي (زي TradingView)

صفحة التوصيات فيها رسم بياني بـ3 لوحات فوق بعض:
1. الشموع اليابانية + SMA50/SMA200 + نطاقات بولينجر + خطوط أفقية للدخول/الوقف/الأهداف/الدعم/المقاومة
2. أعمدة الحجم ملوّنة حسب اتجاه الشمعة (أخضر/أحمر)
3. RSI مع خطوط 30/70 للتشبع البيعي/الشرائي

كله بثيم غامق ومحاور مشتركة (zoom واحد بيأثر على اللوحات التلاتة مع بعض).

## أفضل استراتيجية تداول (Strategy Engine)

بدل نظام واحد عام يتطبق على كل الأسهم، `GET /strategies/best/{symbol}`
بيختبر 5 استراتيجيات مختلفة فعليًا (باك-تيستنج حقيقي، مش تخمين) على تاريخ
**نفس السهم تحديدًا**، ويرشّح الأفضل ليه بالذات:

1. الاتجاه الكلاسيكي (EMA20/50 + RSI + حجم)
2. الاتجاه بالزخم القوي (EMA + MACD + ADX)
3. الاختراق المؤكد بالحجم
4. الارتداد من التذبذب (بولينجر + RSI - عكسية/contrarian)
5. الزخم المدعوم بالحجم (VWAP)

**الترتيب مش بمجرد نسبة نجاح أو Profit Factor خام** - بيتخصم حسب حجم
العينة (`confidence_adjusted_profit_factor`)، عشان استراتيجية بـ11 صفقة
وربح مغري ظاهريًا متطلعش أفضل من استراتيجية بـ300 صفقة وأداء أوثق
إحصائيًا. أي استراتيجية بعدد صفقات أقل من 20 مستبعدة تمامًا من الترتيب
ومعروضة لوحدها. متاح كتاب "🏆 أفضل استراتيجية" في صفحة التوصيات.

## أفضل 5 فرص تلقائيًا (بدون أي تدخل)

صفحة 🎯 التوصيات بقى أول حاجة فيها زرار "🔍 افحص السوق كله دلوقتي" -
بيفحص كل الأسهم في القائمة المنسّقة (39 سهم) من غير ما تحدد رمز أو أي
إعداد، ويرجع أفضل 5 فرص **فعلية** بس:

- خطة تنفيذ صالحة فعلاً (`trade_plan.status == valid_long_setup` - يعني
  R:R اتفحص واتقبل من Risk Engine، مش بس Score عالي)
- مفيش تضارب إشارات (`signal_conflict.is_conflicted == False`)

لو مفيش أسهم مستوفية الشروط، الصفحة بتوضح كده صراحة ("⚪ مفيش فرص فعلية
حاليًا") - وده نتيجة صحيحة، مش خطأ في النظام. الفحص ممكن ياخد وقت (ثواني
لدقيقة) لأنه بيحلل كل سهم من الصفر بما فيه بيانات تاريخية جديدة.

## NO TRADE - عند تضارب المؤشرات بشدة

"محايد" العادي (Hold) يعني السوق هادئ ومفيش زخم كافٍ. **ده مختلف تمامًا عن
"المؤشرات بتتعارك مع بعض فعليًا"** - لو 6 مؤشرات أو أكتر نشطة (مش محايدة)
ومنقسمة بشكل متقارب جدًا بين صاعد وهابط (نسبة ≥ 60%)، النظام بيرفض يجبر
نفسه على توصية شراء/بيع حتى لو الـ Score التجميعي مال لجهة معينة بالصدفة،
ويعرض صراحة:

```
⚪ لا تداول - إشارات متضاربة (NO TRADE)
```

مع سبب واضح (كام مؤشر صاعد مقابل كام هابط) في حقل `signal_conflict` بكل
استجابة `/analysis`. خطة التداول بتتجمّد بنفس المنطق. **الأسهم دي مستبعدة
تلقائيًا من `/screener/bullish`** حتى لو الـ score بتاعها عدّى الحد الأدنى -
كان فيه باگ حقيقي في النسخة الأولى بيسمح لأسهم متضاربة تظهر كـ"فرصة صاعدة"،
اتصلح واتغطى باختبار انحدار مخصص.

## Multi-Timeframe Confirmation

الهدف: جودة الإشارة، مش عددها. سهم ممكن يطلع "شراء قوي" على اليومي رغم إن
الاتجاه العام (الأسبوعي) هابط بشدة - `GET /analysis/{symbol}/multi-timeframe`
بيحلل الإطارين ويطبّق بوابة:

- لو الإطار الأكبر **هابط بقوة** (درجة اتجاه ≤ -40 من فئة الاتجاه بس، مش
  الـ Score الكامل) وإشارة الإطار الأصغر شراء → يتم تخفيف التوصية (شراء
  قوي → شراء، شراء عادي → محايد) وتجميد خطة التنفيذ صراحة
- غير كده، التوصية الأصلية تفضل زي ما هي من غير أي تدخل

متاحة كخيار إضافي (expander) في صفحة 🎯 التوصيات - مش بتستبدل التحليل
الأساسي، بس بتضيف طبقة تأكيد اختيارية.

## متانة الاتصال

كل استدعاء شبكة لمصادر البيانات الخارجية (مباشر، صفحة الأخبار، Yahoo Finance)
بيعيد المحاولة تلقائيًا حتى 3 مرات بتأخير متزايد (1s → 2s → 4s) عند فشل مؤقت
(انقطاع اتصال أو انتهاء مهلة) - `app/data/retry_utils.py`. أخطاء غير مؤقتة
(زي 404) **متتكررش** لأن إعادة المحاولة مش هتحل المشكلة.

`GET /health` بيفحص كل مصدر لوحده (`ok` / `degraded` / `down`) عشان تعرف
بسرعة أي حاجة واقعة من غير ما تجرب كل endpoint يدويًا:
```json
{
  "overall_status": "degraded",
  "sources": {
    "mubasher": {"status": "ok", "detail": null},
    "news": {"status": "down", "detail": "..."},
    "yahoo_finance": {"status": "ok", "detail": null}
  }

```
